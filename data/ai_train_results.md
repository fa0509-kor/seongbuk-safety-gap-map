# AI 학습 결과 v1 (10/26, 개발)

학습 데이터는 `data/ai_patch_stats.md` (AI-Hub 4,673장 → 조각 10,262개, 시설물 단위 70/15/15).
학습은 승인받은 팀원 PC에서만 (AI-Hub 약관: 국외 반출·제3자 제공 금지). 이 문서에는 숫자만 적는다.

## 방법
- 모델: torchvision ImageNet 사전학습 가중치 → 마지막 층만 5종(균열·박리·백태/누수·철근 노출·정상)으로 교체해 재학습
- 증강: 좌우·상하 뒤집기, 밝기 조절
- 회차(에폭) 선택: **검증 세트 클래스 평균 재현율**이 가장 높은 회차. 시험 세트는 마지막에 한 번만
- 1·2·3차 비교도 검증 점수로 함 (시험 점수로 고르지 않음)

## 결과

| 차수 | 모델 | 바꾼 점 | 검증 평균 재현율 (최고 회차) | 시험 정확도 | 시험 평균 재현율 |
| --- | --- | --- | --- | --- | --- |
| 1차 | MobileNetV3-Small | 기본 설정 | 0.594 (4회차) | 60.4% | 54.6% |
| 2차 | MobileNetV3-Small | 조각을 넓게 자르고 클래스를 고르게 뽑음 | 0.553 (2회차) | 48.1% | 49.2% |
| **3차 (채택)** | MobileNetV3-Large | 큰 모델, 8회 학습 | **0.616 (2회차)** | 56.2% | **58.9%** |

3차 채택 근거: 검증 평균 재현율이 가장 높음 (시험 점수가 아니라 검증 점수로 고름).

## 읽는 법
- 재현율 = **실제로 그 결함인 것 중 모델이 찾아낸 비율** (정밀도와 다름). 위험을 놓치지 않는 게 중요해서 재현율 우선
- 정확도 기준선: 항상 '정상'이라고만 답해도 44% (시험 1,512개 중 정상 665개). 평균 재현율 기준선: 무작위 20%
- 앱의 'AI 확신도'는 모델이 스스로 낸 값이라 이 정확도·재현율과 다른 숫자 (섞어 말하지 않기)

## 한계
- 백태·누수를 거의 못 찾음: 절반은 정상, 3분의 1은 박리로 봄. 학습 데이터가 가장 많은 클래스(1,879개)인데도 그래서 라벨·조각 문제일 가능성
- 3차 최고 회차가 8회 중 2회차 → 그 뒤로는 검증 점수가 안 오름 (과적합 가능성)
- 철근 노출 시험 13개라 흔들림이 큼
- 드론으로 찍은 옹벽 사진 학습 → 주민 폰 사진에서는 더 낮을 수 있음

## 다음 (11/5까지, 하나씩)
1. 백태·누수 라벨 점검: 라벨 영역이 넓어서 조각 대부분이 멀쩡한 면인지 확인 → 조각 안 라벨 비율 기준을 두거나 더 좁게 자르기
2. 클래스를 고르게 '뽑기'(2차, 성능 하락) 대신 손실에 클래스 가중치
3. 학습률을 낮추거나 조기 종료로 2회차 이후 과적합 줄이기
4. 직접 찍은 성북구 사진 몇십 장으로 학습 모델 vs Claude API 비교 (AI-Hub 사진은 해외 API에 보내지 않음)

## 앱 연결
- 시연은 Claude API 유지 (`VISION_PROVIDER=anthropic`). 학습 모델은 성능이 오르면 `vision.py`에 provider 'model'로 추가
- 모델 파일을 공개 레포에 올려도 되는지는 AI-Hub 이용약관(결과물 활용 조항) 확인 후 결정
