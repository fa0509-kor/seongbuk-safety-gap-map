### AI 학습 방향 (일정대로 진행, 10/19 PM 결정)
- 클래스: 콘크리트 균열 / 박리 / 백태·누수 / 철근 노출 + 정상 (기획안 v1 4번)
- 데이터 만들기: AI-Hub 라벨은 선·영역 표시 → **라벨 영역을 잘라낸 조각**으로 분류 데이터 생성. 대응: crack·reticular crack→균열, spalling·detachment→박리, efflorescence·leak→백태/누수, rebar→철근 노출. **정상**은 라벨이 없는 영역에서 잘라냄
- 철근 노출: 옹벽 7개뿐 → 샘플 데이터(여러 시설물, rebar 351개) 함께 사용
- 분리: 70/15/15, **같은 원본 사진·같은 시설물의 조각은 한 세트에만**
- 모델: 사전학습된 작은 이미지 분류 모델을 미세조정 → ONNX로 내보내 서버(`vision.py`의 provider `model`)에 연결
- 지표: 클래스별 재현율 우선 + 정밀도·F1·혼동행렬. 성북구 현장 사진(직접 촬영)으로 따로 시험해 차이를 한계로 밝힘
- **약관 주의 (aihub_guide.md 요지: 국외 반출 금지, 승인자 외 제공 금지)**
  - 학습은 본인 PC에서. 해외 서버(Colab 등)에 AI-Hub 파일을 올리지 않는다
  - AI-Hub 사진을 해외 AI API(OpenAI·Anthropic)로 보내 평가하지 않는다. API와 학습 모델의 비교는 직접 찍은 성북구 사진으로 한다
  - 팀원 간 메일 공유 금지. 필요한 사람은 각자 신청 (10/19 공유 내용 중 "메일로 공유"는 하지 않음)
  - 위 두 항목은 약관 원문으로 한 번 더 확인 (개발)

### 보호구역 +30: 경계에서 30m 이내까지 인정 (10/26, PM)

- 발표 문장: "법정 보호구역 경계(경찰청 데이터)를 기준으로, 스마트폰 위치 오차를 감안해 30m까지 인정합니다"

- 직접 그린 그림(SVG)이라 저작권 문제가 없다. 앱 안 카메라를 만드는 방식은 쓰지 않았다(기본 카메라·앨범으로 올리는 기존 방식 그대로).
- AI와 무관하고 저장된 사진에는 아무것도 그려지지 않는다. 안내일 뿐이라 주민이 따르는지는 확인하지 않는다.
- 확인한 것: 모바일 크기 화면에서 예시 표시. 확인하지 못한 것: 예시가 실제로 사진 구도를 개선하는지(주민 반응).
### 제보에 브라우저 식별값을 남김 (11/6, 개발)
- 로그인이 없어서 사람을 특정할 수 없으니, 브라우저가 만든 무작위 값을 제보에 붙여 '같은 브라우저에서 올라온 제보'를 담당자가 볼 수 있게 했다. 반복·몰아서 올리는 제보를 가려내는 참고용이고 점수에는 쓰지 않는다.
- 이름·연락처는 받지 않는다. 식별값은 DB에만 두고 응답에 내보내지 않는다.
- 한계: 브라우저 데이터를 지우거나 시크릿 모드, 다른 폰이면 다른 값이 된다. 일부러 피하는 사람은 못 막는다.
- 이 값이 개인정보에 해당하는지는 확인하지 못했다. 개인정보 처리방침에 '중복·반복 제보 확인용 식별값을 보관한다'는 문구를 넣고 전문가 확인을 받는다.
- 주민이 자기 식별번호(앞 8자리)를 '내 제보' 화면과 제보 화면에서 볼 수 있고, 별명(선택)을 정해 브라우저에 저장할 수 있다(앱을 껐다 켜도 유지, 브라우저 데이터를 지우면 사라짐). 담당자 화면에는 같은 8자리와 별명이 나온다. 별명은 자유 입력이라 실명·연락처를 쓰지 않도록 화면에 안내했다. 별명이 개인정보에 해당하는지는 확인하지 못했다.

### 사진 공개 범위: 조치 완료 건만 (11/6, 팀 결정 요청에 따라 개발)
- **지도와 API 모두** 조치 완료 전 제보의 사진은 제보를 보낸 브라우저(식별값이 같음)에게만 보인다. 조치 완료된 제보는 누구에게나 조치 전·후 사진을 보여 준다.
- 이유: 제보 번호가 지도에 공개돼 있어서 번호만으로 `GET /api/reports?ids=`를 부르면 모든 제보의 사진을 받을 수 있었다. 화면에서만 숨기면 의미가 없어 API도 같은 규칙으로 막았다(`GET /api/reports`, `GET /api/reports/{번호}`, 나도 봤어요·고쳐졌어요 응답). 담당자 화면(`/api/admin`)은 변함없이 모두 보인다.
- 영향: 식별값이 없던 옛 제보(PR 36 배포 전)는 본인 확인이 안 돼 조치 완료 전에는 '내 제보'에서도 사진이 안 보인다. 조치 완료 뒤에는 보인다.
- 남은 위험: 조치 완료 사진에도 얼굴·번호판이 찍힐 수 있고 가리는 처리는 없다(제보 화면에서 찍지 말라는 안내만 있음). 담당자가 공개 전에 확인하는 절차는 아직 없다.

### 별명: 처음에 자동으로 정하고, 직접 정하기는 한 번만 (11/6, 개발)
- 앱을 처음 열면(QR 스캔 직후) 별명이 자동으로 정해진다(예: 푸른다람쥐4821, 형용사+동물+숫자 4자리, 식별값에서 만들어 같은 브라우저는 늘 같은 별명). 실명·연락처를 적을 일이 없고 사진을 올리기 전에 별명을 입력할 필요가 없다.
- 마음에 안 들면 직접 정하기를 **한 번** 할 수 있고, 정하면 고정된다. 이미 직접 정한 별명이 있는 브라우저는 그대로 고정이다. 한 달에 한 번 바꾸는 방식은 쓰지 않는다(별명은 한도 기준이 아니라 표시용이고, 바뀔수록 담당자가 같은 사람인지 가리기 어려워진다).
- 별명과 식별번호는 브라우저에 저장하고 만료가 없다. 브라우저 데이터를 지우거나 시크릿 모드, 다른 브라우저·기기를 쓰면 새로 정해진다(아이폰 사파리는 오래 안 쓰면 저장소가 지워질 수 있다). 그래서 이 제한은 일반 사용자 편의를 위한 것이고 악용을 막는 장치는 아니다.

### 사진 품질 경고와 첫 확인 시간 지표 (11/6, 개발) — 멘토님 자료(p12, p22) 반영
- **흔들림·어두운 사진 경고:** 사진을 올리는 순간 브라우저에서 선명도(라플라시안 분산)와 평균 밝기를 재서 "흔들려/어두워 보여요. 다시 찍어 올리면 더 정확해요"를 사진 메모 칸 위에 띄운다. 막지는 않고 그대로 보내도 된다. 서버·AI 호출이 없어 비용이 들지 않는다.
- 기준값은 가정이다: 선명도 20 미만, 평균 밝기 60 미만. AI-Hub 조각 60장으로 맞췄다(같은 조각을 흐리게 만들면 60장 중 59장이 25 미만, 원본은 4장만 25 미만 = 오경고 약 7%, 어둡게 만들면 60장이 모두 밝기 60 미만, 원본은 0장). **현장 전체 사진과 다르므로 실제 폰 사진으로 다시 맞춰야 한다.** 표면이 매끈한 벽을 찍으면 선명한데도 '흔들림'으로 나올 수 있다.
- **첫 확인 시간:** 담당자 대시보드에 접수→첫 확인 평균·중앙값, 24시간 안에 확인된 비율, 확인 대기 건수와 가장 오래 기다린 시간을 보여 준다. 12주 실증에서 볼 지표의 하나다. 첫 확인은 '접수'에서 다른 상태로 처음 바뀐 시점이다.

### UI·UX 멘토링 반영 (11/9, 개발) — 멘토 메모와 팀장 메모
- **원칙(멘토):** 사용자가 고민하게 만들면 서비스를 떠난다. 처음 보는 사람이 바로 알 수 있게 한다.
- **첫 화면:** 맨 위 '위급한 상황이면 먼저 119'(전화 연결), 빈 공간에 '이렇게 써요' 그림 세 컷, '지도 먼저 보기'는 '지도로 제보 둘러보기'.
- **용어:** 주민 화면의 결함 유형 이름만 쉬운 말로 바꾼다(`frontend/src/lib/labels.js`). DB·AI 분류값과 관리자 화면은 그대로. 콘크리트 균열→콘크리트 갈라짐, 박리→표면 벗겨짐, 백태/누수→흰 얼룩·물 샘, 철근 노출→철근이 드러남.
- **홈 순서:** 제보하기 → 우리 동네 안전 소식(**담당자가 확인을 시작한 제보만** 건수·상태·유형. 접수만 된 제보는 지도에서만 보인다) → 내 제보 단계 → 안전왕 순위 → 처리 과정 → 지도 열기 → 서비스 안내. '동네 지도 열기'는 아래로.
- **동네 지도:** 검색창을 없애고 상태(전체·접수·검토 조치 중·조치 완료·조치 후 재확인 필요)는 칩, 위험 유형은 선택 상자로 고른다. 칩에 건수.
- **공개 범위(11/9 결정): 접수 단계 제보의 사진·설명도 공개하되, 부적절한 사진이 AI 검수에 걸리면 미공개.** `PUBLIC_PHOTOS_AFTER_AI_CHECK` 기본값을 켜짐으로 바꿨다. 검수를 통과한 것만 공개하고, 걸린 사진과 검수를 못 한 사진은 숨긴다(조치 완료 제보도 걸린 사진은 숨김). 설명 글은 사진과 같은 기준. 배포 환경에 AI 키가 없으면 사진이 모두 숨겨진다. 남은 위험: 실제 얼굴·번호판 사진으로 검수 결과를 시험하지 못했다.
- **안전왕 순위:** 담당자가 확인을 시작한 제보 1건당 10점(접수만으로는 점수 없음, 가짜 제보 방지). 1등에 '안전왕' 이름. 제보를 보낸 브라우저 기준이라 폰을 바꾸면 이어지지 않는다. 팀 확인 필요: 점수 기준, 공개 화면에 나오는 별명.
- **포인트·봉사시간:** 안내 페이지(`/guide`)까지만 만들었고 '준비 중'으로 적었다. 점수를 포인트나 봉사시간으로 바꾸는 것, 학생 봉사시간 인정은 **팀 논의가 필요**하다(실명·기관 연동·보호자 동의 문제). 숫자는 정하지 않았다.
- **마이페이지:** 하단바 4개(홈·동네 지도·제보하기·마이페이지)는 그대로 두고 '내 제보' 탭 이름을 '마이페이지'로 바꿨다. 내 제보(단계별 날짜·시간), 내 점수·순위, 서비스 안내·포인트와 봉사시간 링크가 여기 있다. 서비스 안내는 홈 맨 아래에서도 들어간다.
- **체험 제보:** 체험용 사진 3장 중 한 장을 골라 → 사진 확인 → 제보 보내기. 보낸 뒤에는 '체험이 끝났어요' 화면(실제로 제보하기 / 내 제보에서 보기 / 홈으로)을 먼저 보여 준다. 체험 제보는 지도·순위·건수에 나오지 않고 담당자 화면에만 보인다.
- **버그:** 제보 화면에서 단계가 바뀌어도 스크롤이 아래에 남아 '사진 확인하기'를 누른 자리에 '제보 보내기'가 놓였다. 두 번 누르면 제보가 보내졌다. 단계가 바뀌면 맨 위로 보낸다.
- 이번에 하지 않은 것: 제보 화면의 '분석 중' 진행 표시와 '보내기 전 확인' 카드(시안 이미지에 있음), 제보 검토·구청 전달 기준 문서, 발표 문구(계절성 위험 예방, 학생이 풀 수 있는 지역 문제 범위).

### 팀 노션 계획(「프론트 & 백」, 11/9)에 맞춘 재정리 — 개발
앞의 'UI·UX 멘토링 반영'에서 아래가 **바뀌었다**(팀 노션 답변과 계획을 따름).
- **공개 기준:** 담당자가 확인(검토)한 제보만 지도와 홈에 나온다. 접수 상태는 지도에 내지 않고 홈에 '확인 대기 N건' 숫자로만 보인다. 접수 상태 제보의 사진·설명은 본인 브라우저 말고는 내보내지 않는다. 검토 이후 제보의 사진은 AI 공개 검수를 통과한 것만 공개한다(걸리거나 검수를 못 한 사진은 미공개). `PUBLIC_PHOTOS_AFTER_AI_CHECK` 기본값 켜짐은 그대로.
- **지도 필터:** 전체 / 검토 중 / 조치 중 / 조치 완료 / 조치 후 재확인 필요(접수 필터는 없앰). 위험 유형은 선택 상자.
- **홈:** 제목 '안전캐치', 맨 위 제보 과정 4단계 그림과 '자세히 보기'(안내 화면), 사진으로 제보하기, **우리 동네 제보 현황**(확인한 제보 건수·상태 막대, 확인 대기 N건, 최근 제보 진행 막대, 완료 제보는 조치 사진 확인하기), 내 제보, 안전왕 순위, 지도(작게), 서비스 안내, 119. 서버에서 세는 `GET /api/reports/summary`를 쓴다.
- **완료 결과:** 담당자가 완료로 바꿀 때 보수 완료 / 소유자 안내 / 이상 없음을 고른다(새 표 `report_results`, 기존 표 변경 없음). 주민 화면 문구는 "시설 + 결함 + 결과"(예: 옹벽·축대 표면 벗겨짐 · 보수 완료). 노션 예시의 '박리'는 멘토 지적(시민이 모르는 말)에 따라 '표면 벗겨짐'으로 쓴다.
- **관리자:** 접수 제보에 '확인 후 공개' 버튼(= 상태 검토), 완료일 때 결과 선택칸.
- **내 활동:** 하단바 '내 제보'를 '내 활동'으로. 내 제보(단계별 날짜·시간), 내 점수, 서비스 안내 링크, **학생이 할 수 있는 일**(조치 후 재확인 필요한 곳, 봉사 순찰, 제보가 몰린 곳 주의 안내 — 지도 데이터로 계산, 서버 작업 없음).
- **체험 제보:** 서버에 `is_demo`로 저장해 담당자 화면에는 보이게 둔다(시연 흐름 유지). 지도·순위·건수에는 나오지 않는다. 노션 계획의 '체험 제보는 저장하지 않기'와 다르며 사용자가 지금대로 두기로 했다.
