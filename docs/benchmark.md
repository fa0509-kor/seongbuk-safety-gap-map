# 벤치마크 → 기능 연결표

발표 5장(벤치마크)과 9장(시연)을 잇기 위한 문서. "벤치마크에서 본 한계를 우리 화면 어디서 고쳤는지"를 한 줄씩 짚는다.
기준 문서: 노션 「최종 기획안 v1」 3번(벤치마크), 1차 멘토링 자료조사(개발 파트).

## 1. 대표 벤치마크: Bureau Veritas (BV)

- 하는 일: 검사원이 건물·인프라를 직접 점검하고 **점검 확인서**를 발급해서 돈을 번다 (매출 수치는 기획안 v1 기준, 발표 전 원문 재확인)
- 우리가 따르는 것: "점검·기록·확인서"를 파는 구조, 법정 점검 의무가 있는 고객(자치구·대학·아파트)
- 우리가 고치는 것: 아래 3가지

| BV의 한계 | 우리가 바꾼 것 | 화면 | 시연 때 말할 문장 | 상태 |
| --- | --- | --- | --- | --- |
| ① 사람이 전부 간다 (비싸서 전수 점검 못 함) | 공공데이터 규칙으로 **먼저 확인할 곳**을 고름 | 관리자 대시보드 맨 위 '데이터 사전 점검', 주민 지도 회색 점 | "안전시설 5,807곳을 다 가는 대신, 데이터가 먼저 97곳을 골랐습니다" | ✅ |
| ② 의뢰받은 것만 본다 (목록 밖은 안 봄) | 주민 사진 제보 + 관리목록 밖이면 우선순위 가산 | 주민 제보 화면, 관리자 상세 '우선순위 점수' | "삼선동 옹벽처럼 목록에 없던 곳은 주민 사진으로 들어옵니다" | ⚠️ 제보는 됨. 목록 밖 가산(+20)은 지역급경사지 데이터 연결 전이라 현재 0 |
| ③ 확인서 종이로 끝난다 (조치 여부 안 따라감) | 접수→검토→조치→완료 추적, 기한 초과 표시, 기간별 **점검 확인서** | 내 제보 4단계, 관리자 상세 상태 변경, 확인서(보고서) 화면 | "확인서를 발급하고 끝나는 게 아니라, 고쳐질 때까지 따라갑니다" | ✅ |

발표 문장(기획안 v1): **"Bureau Veritas가 종이로 주는 점검 확인서를, 주민과 AI가 채우는 실시간 기록으로 바꿉니다."**

## 2. 1차 자료조사 기업 → 반영된 기능

| 기업 | 본 한계·아이디어 | 우리 기능 |
| --- | --- | --- |
| Nextdoor | 같은 위험이 반복 신고됨 | '나도 봤어요(+1)' → 우선순위 1명당 +5 (최대 +20) |
| Nextdoor | 해결됐는지 알 수 없음 | 내 제보 4단계 상태, 하단바 빨간 점 |

| 인텔리빅스 · 다리소프트 | 고정 CCTV·차도 밖(골목·사유지)은 못 봄 | 주민 스마트폰 사진 제보 |
| 인텔리빅스 | 관제 결과 보고서 자동 작성 | 기간별 점검 확인서 (고정 양식 + DB 집계값, LLM 미사용) |

| Tolemi · 이지스 | 원본 공공데이터 오류는 안 거름 | 공백 탐지 규칙 (좌표 누락·이상, 사용불가 소화전, 소화전 거리) |

## 3. 숫자 (backend/data/summary.json, 10/19 내려받은 공공데이터 기준)

- 안전시설 5,807곳 = 소방용수 4,936 + 무더위쉼터 262 + AED 515 + 어린이보호구역 94
- 먼저 확인할 곳 97곳 (1.7%) = 좌표 누락·이상 19 + 사용불가 소화전 45 + 100m 안 소화전 없음 의심 33
- 화면·확인서 숫자는 DB에서 실시간 계산 (`GET /api/admin/summary`의 `screening`)

**쓰는 법 / 쓰면 안 되는 표현**
- O "규칙에 걸린 97곳부터 확인한다", "현장 점검 대상을 먼저 좁힌다"
- X "나머지 98%는 안전하다", "점검 비용을 98% 줄인다" (근거 없음. 비용 비교는 가정값을 밝힐 때만)
- X 1차 자료조사의 756건·132개 (10/19 재계산에서 재현 안 됨)

## 4. 아직 비어 있는 것

- 목록 밖 가산: 지역급경사지 API 키 → 데이터 연결 시 ②가 숫자로 보임 (개발)
- 비용 비교: BV식 현장 점검 1곳 비용 가정 × 5,807 vs 97 (발표, 가정 명시)
- 경쟁 비교표의 안전신문고 칸: "신고는 받지만 공공데이터 대조·목록 밖 표시는 없음" 근거 확인 (발표)
